# VL-I — predecessor capability and evidence inventory

**Snapshot studied:** 2026-11-19, public default branches of the linked projects. This is a source-oriented intake guide, **not** a new verification run. Claims below are scoped to the cited predecessor documents and their retained test/evidence artifacts; a VL-I demonstration must replay or independently verify them.

VL-I should compose these mechanisms through adapters. **Do not fork all predecessor code or create competing Hypervisors, Ground authorities or storage systems by default.**

## 5. What the source observations do **not** prove

The repository inspection was **not** a live benchmark and did not rerun the cited external CI jobs. Predecessor documentation reflects its own scope and date.

Not yet established for VL-I:
- A single interface that acquires an arbitrary model snapshot, independently interprets it, and runs complete multi-token generation with no opaque model backend.
- A demonstrated general law or quotient allowing trained-model outputs to be reached substantially more cheaply than exact numeric evaluation while preserving an explicit behavioral contract.
- Full, sustained inference on the largest enumerated dense/hybrid/MoE checkpoints *with exactly the same verified execution and recovery obligations*.
- Reconstructing exact unknown trained parameters from screenshots/configuration/metadata alone.
- Portability of the full model computation across unrelated hosts with independent verification and truthful cost accounting.

These are **research objectives**, not reasons to narrow the goal.

## 6. External specifications to verify against

- [Safetensors format](https://github.com/huggingface/safetensors/blob/main/README.md): 8-byte header length; JSON tensor metadata; data offsets relative to data buffer. Validate shape, dtype, header extent and ranges.
- [Hugging Face metadata parsing](https://huggingface.co/docs/safetensors/metadata_parsing): distinguish index/header inspection from accessing actual tensor values.
- [Hugging Face Hub download contract](https://huggingface.co/docs/huggingface_hub/main/guides/download): pin snapshot revisions; verify access restrictions, caching and actual bytes received.
- [Transformers KV-cache semantics](https://huggingface.co/docs/transformers/main/cache_explanation): causal position, mask and cache behavior to compare against the native VL implementation.

## 7. Integration rule

**Prefer an adapter plus one independently checked use case to a new implementation of an existing feature.** For each adopted component record the upstream path, commit revision, interface schema, native receipt meaning, test scope and what it does not claim.

The next research cycle should make this inventory **executable**: pin upstream commits, run the directly relevant tests, emit a machine-readable adapter map, and validate import compatibility.
