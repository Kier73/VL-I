# From a model webpage to a Virtual Layer operation

A model card gives the reader a way to find a checkpoint. The model's trained behavior enters the computation at a different point, when a requested operation consumes values from that checkpoint. This experiment connects both points. It starts on public Hugging Face webpages, follows their file listings to versioned bytes, and asks the existing VL-64 interpreter to evaluate the operations it knows.

## The mathematical step from reading to running

Let the result of browsing be a pinned repository, a config, an index and the observed shard headers. A tensor index gives a shard name. A validated header gives a dtype, shape and payload interval. For a BF16 matrix with width $d$, row $t$ occupies $[h+o+2dt, h+o+2d(t+1))$, where $h$ includes the eight-byte header length and $o$ is the tensor's payload offset. For dense next-token generation the requested observation is $\arg\max_v F_{\theta}(x)_v$. The address calculation supplies the operands of $F$; the interpreter must also supply every required operation and its state.

This suggests a testable meaning of expanding the architecture. Let $C$ be the available typed operators and $D$ the graph described by a newly observed model. A receiver can already execute new graphs by composition when every required node in the requested output's dependency graph has an implementation in $C$ with matching semantics. When a node is missing, record its input shapes, weight encoding, precision rules, state transition and expected outputs. A proposed implementation expands $C$ after it passes independent comparisons on held-out inputs. The published experiment exercises graph instantiation within the supported Llama profile. Learning and admitting a new operator remains an experiment to build.

## Live observations

**The isolated seed found SmolLM-135M through Hub search and completed “The capital of France is” with “ Paris” (token 7042).** An external tokenizer supplied five token IDs. The seed followed the model card, mutable tree and pinned tree, acquired the weights, and ran the decoder locally. A separate CPU PyTorch evaluation selected the same token. Across all 49,152 logits, the maximum absolute difference was 0.000027653 against the prespecified tolerance of 0.0002. This is one greedy step on one prompt. [Complete generation receipt](../experiments/model_pages/2026-11-22-smollm-generation.json)

The program occupied **26,723 bytes** on disk and **65,492 bytes** of expanded Python. The four webpages added 927,282 response bytes. The seed fetched 538,120,784 shard bytes including header reads and staged the entire verified shard in a temporary file. The decoder made 35,662 logical reads totaling 2,237,317,632 weight bytes while processing the five-token prefix. The size budget applies to the interpreter; the measured run used ordinary CPU arithmetic, temporary storage and a host Python installation. It establishes fidelity for this observation. A compute saving would require a separate comparison of equivalent executions.

- A free-text search for `SmolLM-135M` yielded six inspected configurations. VL-I read the displayed result links, then visited their model cards and config files concurrently. All six declared a Llama model type. The survey records the source commit per result and spent zero weight bytes. [Search receipt](../experiments/model_pages/2026-11-22-search.json)
- Qwen's root directory led to 18 shards, 1,199 tensors and 55,562,855,904 declared payload bytes. The compact seed read 267,400 bytes of config, index and headers to map them, in addition to the webpages. Its Llama decoder declined the Qwen configuration. A targeted VL-I query then read a single 10,240-byte trained embedding row and matched its earlier SHA-256. [Embedding receipt](../experiments/model_pages/2026-11-22-embedding-rows.json)

The compact parser reached shard 3, which contains 1,160 tensors with the unsupported `F8_E8M0` encoding, including `layers.0.attn.wkv.scale`. VL-I used the existing quantized-header reader to find row 63204 of `embed.weight`; its 10,240 bytes matched the earlier DeepSeek measurement. The two models give different bytes at that token coordinate. ## What an adaptive OS could measure next

For an intention $q$, let $S(O)$ contain the candidate model states consistent with the observations $O$ so far. The exact stopping rule is $|\{q(s):s\in S(O)\}|=1$. For instance, a complete index often settles which shard contains a named tensor. The same index can describe two checkpoints whose unseen row values differ, so it cannot by itself settle a dot product against that row. If the true state lies outside the candidate set, uniqueness within the set gives no guarantee. E-CPU's explicit contradiction outcome matters here.

A practical OS experiment would give two workers the same pinned model, a held-out causal input and a new, previously unsupported layer transition. The first worker searches published config and tensor evidence and proposes a composition of local operators. The second checks the proposed graph against an independently implemented reference on held-out prefix states, including a second token that consumes the first token's cache. Record the first operator or state boundary that diverges. On success, save the graph, numerical contract and versioned source coordinates, then repeat on a second checkpoint of the same family.

Charge discovery, network bytes, local reads, arithmetic, temporary storage and verification separately. A cheaper future query must repay the initial discovery cost. The earlier DeepSeek router trial illustrates the distinction: its proposed stopping rule found the right experts while eliminating too little work to repay its first scan. ## Reproduction

Use sibling checkouts of this VL-I branch and VL-64 revision `da4eb8f633ba8ce6503c87355864c7f367dcb5af`. The seed needs only the Python standard library. The independent language-model comparison additionally uses NumPy, tokenizers, Transformers and CPU PyTorch. Supply the local reference snapshot of SmolLM-135M revision `1d461723eec654e65efdc40cf49301c89c0c92f4`. That directory supplies the experiment tokenizer and the independent oracle. The isolated seed receives token IDs and obtains its weights through the public webpages. [Page-enabled seed and source](https://github.com/Kier73/VL-64/tree/da4eb8f633ba8ce6503c87355864c7f367dcb5af)

~~~sh
python -m examples.search_model_pages --vl64 ../VL-64 --query SmolLM-135M --limit 6 --out artifacts/model-search.json
python -m examples.model_page_rows --vl64 ../VL-64 --all-headers --out artifacts/model-page-rows.json
python -m examples.model_page_generation --vl64 ../VL-64 --reference-snapshot /path/to/SmolLM-135M --out artifacts/model-page-generation.json
~~~
